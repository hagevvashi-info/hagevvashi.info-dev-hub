# Current Entry Schema

## Status

**OUTDATED** — This document describes the existing schema. See **proposed/** for evolution plans.

## Existing Implementation

The `Entry` struct in `agent.go` defines the queue entry format:

```go
type Entry struct {
    SessionID   string              // Unique session identifier
    Command     string              // Command to execute
    Arguments   []string            // Command arguments
    Environment map[string]string   // Environment variables
    CreatedAt   time.Time           // Creation timestamp
    AcknowledgedAt *time.Time       // Acknowledgment timestamp
}
```

## Field Descriptions

### SessionID
- **Type**: `string`
- **Required**: Yes
- **Semantics**: Uniquely identifies this queue entry and the session it belongs to
- **Generated By**: Client at entry creation time (typically UUID format)
- **Immutable**: Yes

### Command
- **Type**: `string`
- **Required**: Yes
- **Semantics**: The command/program name to execute
- **Example**: `"tty-session-handler"`, `"script.sh"`, `"python"`

### Arguments
- **Type**: `[]string`
- **Required**: No (can be empty)
- **Semantics**: Command-line arguments passed to the command
- **Example**: `["-v", "--timeout=30"]`

### Environment
- **Type**: `map[string]string`
- **Required**: No (can be empty or nil)
- **Semantics**: Environment variables to set when executing the command
- **Example**: `{"PATH": "/usr/bin", "USER": "agent"}`

### CreatedAt
- **Type**: `time.Time`
- **Required**: Yes
- **Semantics**: Timestamp when the entry was enqueued
- **Set By**: Queue.Put() automatically
- **Format**: RFC3339

### AcknowledgedAt
- **Type**: `*time.Time` (optional pointer)
- **Required**: No
- **Semantics**: Timestamp when the consumer acknowledged completion
- **Set By**: Queue.Ack() after acknowledgment
- **Initial Value**: nil

## Limitations

### User Traceability
- No explicit user/principal field
- Cannot distinguish between different users
- Limits audit capabilities

### Audit Trail
- `AcknowledgedAt` provides end timestamp only
- No information about who acknowledged
- Cannot track partial failures or retries

### Access Control
- No per-user filtering possible
- Cannot implement user-scoped queue views
- Security model lacks fine-grained control

### Delegation Scenarios
- Cannot distinguish user-submitted vs. system-submitted entries
- Makes it difficult to implement approval workflows

## Known Issues

1. **SessionID Collision**: No validation that SessionID is globally unique
2. **Command Injection**: Environment map accepts arbitrary values without validation
3. **Timestamp Precision**: CreatedAt is generated by queue, AcknowledgedAt by consumer
4. **Schema Evolution**: Adding fields requires migration logic

## Evolution

See `proposed/QUEUE_ENTRY_SCHEMA_DESIGN.md` for planned improvements addressing these limitations.

## Usage Example

```go
entry := Entry{
    SessionID:   "session-123-abc",
    Command:     "tty-handler",
    Arguments:   []string{"-timeout=30"},
    Environment: map[string]string{"TTY_MODE": "interactive"},
    CreatedAt:   time.Now(),
    AcknowledgedAt: nil, // Not yet acknowledged
}

queue.Put(entry) // Add to queue
retrieved, _ := queue.Next() // Agent retrieves
queue.Ack("session-123-abc") // Agent acknowledges
```
