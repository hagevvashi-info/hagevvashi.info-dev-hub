# csv-parseスキル — 設計コンテキスト

## 設計思想

### 根拠とした調査内容（出典と引用）

今回のスキル構築にあたり、AIエージェントの挙動を安定させるためのベストプラクティスとして、以下の公式ドキュメントおよび技術記事の知見を反映しています。

**1. Claude Code Skillsのベストプラクティスについて**
* **出典:** Anthropic ヘルプセンター「カスタムスキルの作成方法」
* **引用:** > 「最高のスキルは以下の特徴があります： 特定の反復可能なタスクを解決する / Claudeが従うことができる明確な指示を持つ / 有用な場合は例を含む / 使用すべき時期を定義する / すべてを行おうとするのではなく、1つのワークフローに焦点を当てている」
* **適用した設計:** 単に「DuckDBを使え」という曖昧な指示ではなく、「プレビュー」「集計」「エラー時の対処」という具体的なワークフローに分け、AIがそのままターミナルで実行できるシェルコマンドの「例（Example）」を明記しました。

**2. DuckDBを用いた実践的なCSVの読み込み手法について**
* **出典:** Zenn 技術記事「DuckDB 50本ノック - 実際に使用した例から抜き出したtips集」
* **引用1:** > 「CSVファイルを直接クエリ: DuckDBではローカルにあるcsvをこのような感じで一文で読むことができます。非常に楽で助かります。 `con.sql("SELECT * FROM 'data.csv'")`」
* **引用2:** > 「RFC規格に沿っていないガタガタの(列数が行ごとに違うなど)csvを読むときにpandasなどでは読めないが、以下のコードでnullで埋めて読めるようになります。 `con.sql("SELECT * FROM read_csv('irregular.csv', null_padding=true)")`」
* **適用した設計:** 上記の知見をCLI（`duckdb -c`）形式に適用し、スキル内に組み込みました。特に「引用2」のエラー回避策（`null_padding=true`）をあらかじめ手順に含めることで、Claudeがパースに失敗した際に自己解決（フォールバック）できる能力を高めています。
